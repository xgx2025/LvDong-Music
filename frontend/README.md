# 律动音乐 · Vue 前端

基于 Vue 3、TypeScript、Vite、Vue Router 和 Pinia 的音乐前端。页面沿用旧站的蓝绿渐变、玻璃卡片与各页面原有明暗配色。

## 已迁移页面与功能

- 首页与公开搜索：歌曲、歌手、分页、空结果和错误重试。
- 账号：邮箱登录、注册、验证码、密码重置、退出、受保护路由与登录后返回。
- 个人中心：当前用户资料、头像与资料编辑、音乐人资格、申请和审核状态。
- 音乐人上传：音频、封面、可选歌词、格式与大小检查、服务端资格校验。
- 收藏：登录用户独立收藏状态、收藏与取消、本人收藏分页。
- 歌曲详情：已发布歌曲信息、评论分页、发布、回复与点赞。
- 播放器：单 Audio 引擎、跨路由连续播放、队列、进度、音量、展开、LRC 同步及歌词跳转。
- 识曲：沿用旧站语音转文字加歌词识别，支持直接输入歌词；不是音频指纹识别。
- AI助手：保留为明确标识的本地演示。意见反馈没有对应旧服务接口，支持导出到本机，不显示发送成功。

以上音乐业务、媒体及本地封面/歌词资源均由[独立后端](../backend/README.md)提供。专辑、歌单独立检索及第三方 OAuth 旧站没有完整服务端实现。

## 运行与构建

依赖版本由 lockfile 锁定。

```sh
cd frontend
npm ci
npm run dev
```

```sh
npm test
npm run build
```

构建先执行 TypeScript 类型检查，产物在 `dist/`。使用 hash 路由，个人中心为 `/#/profile`，登录为 `/#/login`。

## 服务连接

可参考 [.env.example](.env.example) 创建本地配置。

| 配置 | 作用 |
| --- | --- |
| `API_PROXY_TARGET` | 开发环境 Boot 接口代理，默认 `http://127.0.0.1:8081` |
| `VITE_API_BASE` | Boot API 根地址，默认同源 |
| `VITE_APP_BASE` | 静态资源部署前缀，默认 `/` |
| `VITE_LEGACY_BASE` | 仅保留未识别旧资源路径的兼容选项，现有音乐业务无需配置 |

先按后端说明显式执行会话、验证码和音乐人材料增量脚本，并配置文件存储、邮件和识曲服务。新前端的音乐业务无需运行旧 WAR。

生产环境需配置 `/api` 反向代理；Vite 开发代理不会进入生产产物。跨域部署需服务端显式允许应用来源及 Authorization。HTTPS 页面应连接 HTTPS 服务。`VITE_` 配置会公开到浏览器，不可包含密钥或凭证。

## 登录与播放边界

登录由 Boot 签发不透明双令牌，沿用原有 JSON 字段，并发 401 只刷新一次，业务请求最多重试一次。默认仅保留在页面内存；勾选“在当前标签页保持登录”后使用 sessionStorage，重载时先向服务端续期，退出清理并请求服务端撤销。不会自动读取旧站 localStorage，也不存密码。Boot会话在数据库中撤销，更新后的旧WAR也检查该记录；旧JWT仍只有进程内黑名单。

登录凭证同时用于 Boot 媒体播放，切换身份与退出停止播放但保留队列。手工播放凭证仍可作为未登录时的连接选项，不代表账号身份。媒体准备最长等待五分钟，失败或超时可重试。

HLS.js 向清单、切片和密钥发送 Bearer；原生 HLS 使用查询 token，由 Boot 清单接口传播鉴权。真实部署、邮件投递、第三方识曲服务、Safari 原生 HLS 和实际移动设备需分别联调，隔离测试不代表这些外部环境已验收。
